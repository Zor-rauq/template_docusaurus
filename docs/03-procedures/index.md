# Procédures

Objectif : **décrire comment agir**. Cette famille regroupe les procédures pas à pas — qu'elles
soient répétées régulièrement (déploiement, installation) ou réservées aux urgences (incident,
rollback).

On distingue généralement deux formats :

- **Runbook** : suite d'étapes séquentielles pour réaliser une opération (déploiement,
  restauration, montée de version...).
- **Checklist** : liste de points à vérifier, sans ordre strict imposé (revue avant mise en
  production, onboarding...).

## Contenu de cette section

- [Modèle de runbook](./runbook) — pour une procédure pas à pas.
- [Modèle de checklist](./checklist) — pour une liste de vérifications.

## Bonnes pratiques

- Rédiger les étapes comme si la personne qui les exécute découvrait l'outil (pas de raccourci
  implicite).
- Indiquer la **durée estimée** et les **prérequis** en tête de procédure.
- Tester la procédure régulièrement pour vérifier qu'elle reste à jour.
